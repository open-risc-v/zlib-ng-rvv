# zlib-ng adler32：两档 LMUL 实测与"负优化"判定

- 日期：2026-11-16
- 上游：`zlib-ng/zlib-ng` @ `6727d883…`
- 真机：SpacemiT K3 / <distro>，RVV 1.0，**vlenb=32 / VLEN=256**
- 三侧对照（同一 `-march=rv64gcv`，唯一变量是向量实现）：

| 侧 | 源码 | 配置 | 说明 |
|---|---|---|---|
| off | `baseline` | `-DWITH_RVV=OFF` | 纯 C（scalar unrolled） |
| old | `baseline` | `-DWITH_RVV=ON` | 上游原内核：`e8m1/u16m2/u32m4`，每 21 block 一次 `vremu` |
| new | `src` | `-DWITH_RVV=ON` | 本次试验：加宽一档 `e8m2/u16m4/u32m8` |

三侧产物哈希完全一致：

```
in=200003 out=73562 crc=2644adc5 fnv=3bb0c93b653afa83
```

说明加宽改动**功能正确**，差别只在性能。

## 1. 内核级（16 MiB adler32，真机 5 轮）

| 侧 | adler16M_ns | ns/byte | 相对 off |
|---|---|---|---|
| off（C） | 3632777–3648443 | 0.217 | 1.000× |
| old（`e8m1`） | 3935317–3949651 | 0.235 | **0.928×** |
| new（`e8m2`） | 4308816–4324108 | 0.257 | **0.843×** |

## 2. 为什么"加宽"反而更慢

`e8m2` 把累加器推到 `u32m8`——8 个物理寄存器。K3 的向量寄存器组只有 32 个，
`u32m8` 的 `vwaddu.wv` 每指令要写 8 个 reg，加上 `u16m4` + `u8m2` 同时活跃，
寄存器压力直接翻倍，编译产物出现 spill；而每次迭代搬运的字节数从 32 变 64，
**指令条数减半、但单指令代价涨得更多**。净结果是阶段性负优化。

这说明这条内核的天花板不在 LMUL，而在"8 位数据要两次 `vwaddu` 加宽"这个形态本身：
每 32 字节至少要 2 条加宽指令，而标量 unrolled 版本靠 L1 带宽就能跑满。

## 3. 关于"屏蔽"（已评估，未采用）

既然 RVV 版恒为负值，直觉做法是在 `functable.c` 的 `RISCV_RVV` 分支里不注册
`adler32_rvv`，让它回落到 C。实测这条路**不能只改一处**：

1. 只删两行会立即触发 `init_functable()` 的 `FUNCTABLE_VERIFY_ASSIGN` 断言
   （`Zlib-ng functable failed initialization!` + `abort()`）——因为 `ft` 是
   `memset(0)` 的，未赋值的函数指针就是 NULL。
2. 要让它回落，必须同时定义 `ADLER32_FALLBACK`；但当前 `WITH_RVV=ON` 且
   `-march=rv64gcv` 时 `riscv_natives.h` 会定义 `RISCV_RVV_NATIVE`，而
   `riscv_functions.h` 的 `ADLER32_FALLBACK` 只在 `#ifndef RISCV_RVV_NATIVE` 下定义。
3. 还要处理同一处的 `#undef native_adler32 / #define native_adler32 adler32_rvv`
   宏映射，否则 C 侧仍会被重定向回 RVV。

即改动面为 3 处宏逻辑 + 1 处派发表，换来整链约 **2.4%**（adler32 只占 deflate 的
0.3 ms / 12.3 ms）。判定**不划算**，保持上游默认（RVV 启用），把结论落到文档，
不在 rollout 阶段引入派发层风险。

如果将来换到 VLEN ≥ 512 的板子（每指令搬 128 字节、加宽开销摊薄），
值得用本目录的 `scripts/g3-adler-reeval.sh` 重跑一次三侧对照再定。

## 4. 整链参照（未受本次试验影响）

同一轮 bench 的 deflate 1 MiB：off 12.33–12.39 ms、on 10.17–10.24 ms = **1.208×**，
与既有 G3 结论（deflate 1.20×）一致。

## 5. 复现

```bash
./scripts/g3-adler-reeval.sh    # 编 off / old / new 三侧，qemu 比哈希并出 bench
# 真机
zlib-adler-off | zlib-adler-on | zlib-adler-new
```
